# Collatz（3n+1）猜想

自己想做的第一个「数学问题」程序：随便给一个正整数，看它要跌多少次才能变回 1。

又叫 **3n+1 问题**，也叫**冰雹序列**（因为数会像冰雹一样上上下下，最后还是落地）。

## 规则

- 偶数 → 除以 2
- 奇数 → 乘 3 加 1
- 一直做，最后一定会落到 1（**这就是猜想本身，至今没人能证明**）

比如从 6 出发：

```
6 → 3 → 10 → 5 → 16 → 8 → 4 → 2 → 1        共 8 步
```

注意它先掉到 3，又弹到 16，这就是「冰雹」这个外号的由来。

## 怎么做的

```c
while (a != 1)
{
    if (a % 2 == 0)
    {
        a = a / 2;
    }
    else
    {
        a = a * 3 + 1;
    }
    count++;
}
```

## 用到的知识点

- `while` 循环（循环次数事先**不知道**，所以用 `while` 而不是 `for`）
- `if / else` 二分支
- `%` 取余判断奇偶
- `long long` 配 `%lld`：奇数要 ×3+1，数会疯涨，`int` 会溢出

## 踩的坑

### 1. 输入 `0` 会死循环

`0` 是偶数 → `0 / 2` 还是 `0` → 永远是 `0` → 永远回到同一句，程序空转。

### 2. 输入负数也会死循环（这个坑最深）

C 语言里**负数的余数跟着被除数走**：

```c
-1 % 2 == -1      /* 不是 1！ */
```

所以下面两个判断对 `-1` **全都是假**：

```c
if (a % 2 == 0) { ... }    /* false */
if (a % 2 == 1) { ... }    /* false —— -1 % 2 是 -1，不是 1 */
```

两个分支都进不去 → `a` 一动不动 → 死循环。

正确写法是用 `else` 兜底，只判断「是偶数」这一件事：

```c
if (a % 2 == 0)
{
    a = a / 2;
}
else          /* 剩下的必然是奇数，不用再写条件 */
{
    a = a * 3 + 1;
}
```

### 3. 不检查 `scanf` 的返回值会打印垃圾值

输入 `abc` 或直接按 Ctrl+Z（EOF）时，`scanf` 一个数都没读到，`a` 里是**栈上的垃圾内存**，程序照跑不误，输出莫名其妙的结果（当时跑出来 206、213 这种数）。

```c
if (scanf("%lld", &a) != 1)
{
    printf("输入无效\n");
    return 1;
}
```

`scanf` 返回的是**成功读到的项数**，读到 1 个才算成功。

### 4. `while (a > 1)` 不如 `while (a != 1)`

用 `a > 1` 时如果真出了意外（比如溢出成负数），循环会直接退出，**默默算出错误答案**；用 `a != 1` 至少不会假装成功。

## 验证

| 输入 | 步数 |
|---|---|
| 6 | 8 |
| 27 | 111 |
| 97 | 118 |
| 100 | 25 |

27 这个数特别有名：它才 27，却要弹 **111 步**，最高冲到 9232。

`1 ~ 200` 全部跑过一遍，没有不收敛的，也没有卡死的。

非法输入 `0`、`-1`、`-5`、`abc`、EOF 全部输出「输入无效」并以退出码 1 结束。
