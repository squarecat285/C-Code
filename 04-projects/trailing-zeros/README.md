# n! 末尾有几个连续的 0

自己想的一道数学题：**`n!`（n 的阶乘）算出来之后，末尾挂着几个 0？**

比如 `10! = 3628800`，末尾是 **2** 个 0。

前后写了两个版本：先写出能跑通的循环版，后来又想通了快得多的公式版。

## 为什么不能直接算

`20!` 就已经是 `2432902008176640000`，再大 `int` 和 `long long` 都存不下。所以**只能动脑筋，不能硬算**。

## 核心思路

末尾的每个 `0` 都要消耗一个因子 `10`，而 `10 = 2 × 5`。

`n!` 里 `2` 的个数**永远比** `5` 多（每两个数就有一个 2，可每五个数才有一个 5），所以：

> **能凑出多少个 10，完全由 5 的数量决定。数 5 就行了。**

两个版本的差别，只在「怎么数这 5」。

## 两个版本

| 版本 | 文件 | 做法 | 复杂度 |
|---|---|---|---|
| v1 | [`v1_loop.c`](v1_loop.c) | 挨个数：遍历 `1 ~ n`，把每个数里的 5 因子一个个剥出来 | `O(n)` |
| v2 | [`v2_formula.c`](v2_formula.c) | 算总数：直接 `n/5 + n/25 + n/125 + …` 逐层累加 | `O(log₅ n)` |

`n = 1000` 时，v1 要转约 1000 圈，v2 只要 **5 圈**。

### v1：挨个数（循环版）

```c
for (int i = 1; i <= n; i++)
{
    int t = i;
    while (t % 5 == 0)
    {
        count++;
        t = t / 5;
    }
}
```

### v2：算总数（公式版）

```c
while (n > 0)
{
    count += n / 5;
    n /= 5;
}
```

原理是**换了个数法**：

- 至少含 1 个 5 的数有 `n/5` 个
- 至少含 2 个 5 的数（25 的倍数）有 `n/25` 个
- 至少含 3 个 5 的数有 `n/125` 个
- ……

把它们全加起来，正好等于「每个数的 5 因子个数」的总和——**正是 v1 数的那个东西**，只是不用真的去遍历。

`n /= 5` 让 `n` 一步步缩到 0，循环自然结束，不用事先知道要转几圈。

## 每个版本用到的知识点

- **v1**：`for` 与 `while` 嵌套、用 `%` 和 `/` 剥因子、`i = 0` 死循环的教训、`scanf` 返回值检查
- **v2**：`while (n > 0)` 边算边缩、复合赋值 `+=` 和 `/= `、`scanf` 返回值检查

## 踩的坑

### 1. `i` 从 0 开始会死循环

第一版写成了 `for (int i = 0; i <= n; i++)`。`i = 0` 时 `t = 0`，而：

- `0 % 5 == 0` → **永远成立**，循环进得去
- `0 / 5 == 0` → **永远还是 0**，`t` 一点儿没变

内层 `while` 变成永动机，程序卡死（当时按 F5 调试就是卡在这儿）。改成 `i = 1` 就好了。

> **教训：只要循环体里有 `/` 或 `%`，先想清楚 0 进去会怎样。**

### 2. `while (n > 0)` 这个条件 v2 里同时挡掉了 0 和负数

`n = 0` 或 `n = -5` 时循环一次都不进，直接输出 0。这算不算 bug？见下面「待办」。

### 3. 两个版本的输出格式不一样

`v1_loop.c` 只打印数字，`v2_formula.c` 打印 `末尾连续 0 的个数:数字`。

自己对着看没问题，但如果要**对拍**或者**提交到在线判题**，多余的字会被判错，得把前缀去掉。

## 验证

| n | 答案 | v1 | v2 |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 1 | 0 | 0 | 0 |
| 4 | 0 | 0 | 0 |
| 5 | 1 | 1 | 1 |
| 25 | 6 | 6 | 6 |
| 125 | 31 | 31 | 31 |

`1 ~ 120` 两个版本逐个对拍，**错 0 个**；再用独立公式 `n/5 + n/25 + n/125` 复核 v1，也是**错 0 个**。

两个文件都过 `gcc -Wall -Wextra`，零警告。

## 为什么保留两个版本

和 [`guess-number/`](../guess-number/) 一样，这两个文件连起来是一条学习轨迹：

**v1 是「照着思路硬写出来的」，v2 是「想通了背后的规律之后写出来的」。**

v1 更有价值的地方在于——它把「5 的个数决定末尾 0 的个数」这件事**用代码一字一句地做了一遍**，所以 v2 那个公式才不是凭空冒出来的。将来回头看，能清楚看到自己是怎么从「能做出来」走到「做得更聪明」的。
