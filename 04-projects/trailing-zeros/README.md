# n! 末尾有几个连续的 0

自己想的一道数学题：**`n!`（n 的阶乘）算出来之后，末尾挂着几个 0？**

比如 `10! = 3628800`，末尾是 **2** 个 0。

## 为什么不能直接算

`20!` 就已经是 2432902008176640000，`int` 和 `long long` 都存不下更大的了。所以**只能动脑筋，不能硬算**。

## 思路

末尾的每个 `0` 都需要一个因子 `10`，而 `10 = 2 × 5`。

`n!` 里 `2` 的个数**永远比** `5` 多（每两个数就有一个 2，可每五个数才有一个 5），所以：

> **能凑出多少个 10，完全由 5 的数量决定。** 数 5 就行了。

写出来的代码就是：把 `1 ~ n` 每个数里的 5 因子反复 `/ 5` 剥干净，剥一次记一个。

```c
for (int i = 1; i <= n; i++)
{
    int t = i;
    while (t % 5 == 0)
    {
        count++;
        t = t / 5;
    }
}
```

这个版本跑 `1 ~ 120` **全对**。

## 踩的坑：`i` 从 0 开始会死循环

第一版写成了：

```c
for (int i = 0; i <= n; i++)     /* 错！从 0 开始 */
{
    int t = i;
    while (t % 5 == 0)
    {
        count++;
        t = t / 5;
    }
}
```

`i = 0` 时 `t = 0`，而：

- `0 % 5 == 0` → **永远成立**，循环进得去
- `0 / 5 == 0` → **永远还是 0**，`t` 一点儿没变

于是内层 `while` 变成永动机，程序卡死。改成 `i = 1` 就好了。

**教训：只要循环体里有 `/` 或 `%`，先想清楚 0 进去会怎样。**

## 更快的写法（还没写进来）

数学上有现成公式，只要 `O(log₅ n)` 次运算：

```
Z(n) = n/5 + n/25 + n/125 + n/625 + ...
```

一直加到除数为 0 为止。原理是「至少含一个 5 的数有 `n/5` 个，至少含两个 5 的有 `n/25` 个……」逐层累加，正好把每个数的 5 因子个数都数全。

## 验证

| n | 期望 | 实测 |
|---|---|---|
| 0 | 0 | 0 |
| 1 | 0 | 0 |
| 4 | 0 | 0 |
| 5 | 1 | 1 |
| 25 | 6 | 6 |
| 125 | 31 | 31 |

`1 ~ 120` 对着公式 `n/5 + n/25 + n/125` 逐个对拍，**错 0 个**。

`gcc -Wall -Wextra` 编译零警告。
