# braces-and-if：`if` 只管紧跟的那一句，大括号别省

- **日期**：2026-10-14
- **出处**：`01-textbook/sequence/change_maker.c`
- **关键词**：if、大括号、缩进陷阱、悬垂 else

## 现象

只打印非零行时，写成这样（**能正常跑，没有警告**）：

```c
if (on_1 != 0)
    printf("50 元 * %d 张\n", on_1);
```

五句都这么写，功能完全正确。

## 原因

这不是 bug，是**埋着的雷**。

`if` 只控制**紧跟它的那一条语句**。假设两个月后你想加一行：

```c
if (on_1 != 0)
    printf("50 元 * %d 张\n", on_1);
    printf("50 元合计: %d 元\n", on_1 * 50);   /* ← 看起来在 if 里，其实在外面！ */
```

**第二行永远会执行**，哪怕 `on_1` 是 0。

而且缩进看起来完全正常，**肉眼扫过去发现不了**。编译器通常也不会警告。

这种「代码看起来是一个意思，实际是另一个意思」的情况，是 bug 里最难查的一类——你会反复检查那句 `printf`，永远想不到问题出在**括号**上。

## 教训

**一律带大括号，哪怕里面只有一句。**

```c
if (on_1 != 0)
{
    printf("50 元 * %d 张\n", on_1);
}
```

很多公司的代码规范**强制**要求这一点，正是因为上面那个坑。

**一句话记住它**：

> 大括号不是给编译器看的，是给三个月后的你看的。
