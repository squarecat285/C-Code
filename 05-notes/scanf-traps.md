# scanf-traps：scanf 失败时不会告诉你，它只是不写变量

- **日期**：2026-10-14
- **出处**：`01-textbook/sequence/change_maker.c`
- **关键词**：scanf、返回值、死循环、EOF、未初始化变量

## 现象

### 失败模式 A：死循环

程序要求反复输入直到金额足够。但如果输入只有一次：

```text
$ echo "120 100" | timeout 3 ./change_maker
请输入应付金额 实付金额:实付金额不足，请重新输入
请输入应付金额 实付金额:实付金额不足，请重新输入
请输入应付金额 实付金额:实付金额不足，请重新输入
... （3 秒内刷了 1,955,920 行，被强杀）
```

**退出码 = 124**（表示被 timeout 杀掉，不是正常结束）。

### 失败模式 B：打印垃圾数字

输入不是数字时：

```text
$ echo "abc" | ./change_maker
请输入应付金额 实付金额:应收: 1 元
实收: 32758 元
找零: 32757 元
---找零明细---
50 元 * 655 张
```

**顾客给了 655 张 50 元。** `32758` 是哪来的？没人知道——这是内存里的垃圾数据。

## 原因

原来写的是：

```c
scanf("%d %d", &price, &pay);   /* 返回值被扔掉了 */
```

`scanf` 的返回值是**成功读到的项数**。这里要读 2 个，所以正常情况下返回 `2`。失败时它返回 `0` 或 `EOF`，并且——

> **`scanf` 失败时不会往变量里写任何东西，变量保持原值。**

- **失败模式 A**：输入流耗尽（EOF）。`price`/`pay` 还是上一轮的 120 和 100，`change` 还是负数，`if (change >= 0)` 不成立，**不 break**，再问一遍——还是读不到，还是 -20……无限循环。
- **失败模式 B**：第一轮就失败。此时 `price`/`pay` **从未被赋值过**，是栈上的垃圾。详细原理见 [uninitialized-variables.md](uninitialized-variables.md)。

关键区别：**人打字时错误是有限的**（手滑一次，下次打对就好了）；**程序读管道、读文件时错误是无限的**（它会一直读到同一个坏数据）。所以「我手动试了没问题」和「程序没 bug」是两回事。

## 教训

```c
if (scanf("%d %d", &price, &pay) != 2)
{
    printf("输入无效，程序结束\n");
    return 1;
}
```

还想让用户重试，就要顺手清掉缓冲区里的脏数据：

```c
if (scanf("%d %d", &price, &pay) != 2)
{
    printf("输入无效，请重新输入\n");
    int c;
    while ((c = getchar()) != '\n' && c != EOF) { }   /* 清空这一行 */
    continue;
}
```

⚠️ **`continue` 必须配这个清理循环**。不清理的话坏数据一直卡在缓冲区里，下一轮 `scanf` 又读到同一份，照样死循环。

**一句话记住它**：

> `scanf` 是有返回值、会失败的函数，不是一条「命令」。读到几个才算成功，就要写几个。
