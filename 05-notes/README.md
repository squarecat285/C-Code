# 学习笔记

## 只记三样东西，不要抄书

1. **踩过的坑** —— 比如「`scanf` 读 double 要用 `%lf`，读 float 才用 `%f`」
2. **自己搞懂了的原理** —— 比如「整数除法 `5/2` 得 2；想得小数，至少要有一个操作数是浮点」
3. **还没搞懂的问题** —— 先写下来，学到后面再回来回答

抄书没有用，笔记的价值在于**那是你自己的话**。

## 格式

一个主题一个文件，照 [`_template.md`](_template.md) 抄：

```text
# 标题：一句话说清这是什么坑
- 日期 / 出处 / 关键词
## 现象      ← 我看到了什么。贴真实输出，不要转述
## 原因      ← 为什么会这样，讲到机制
## 教训      ← 以后怎么写，给一句能背下来的话
## 还没搞懂   ← 没有就删掉这节
```

**「现象」这一节最关键。** 一定要贴终端里的**原样输出**（含退出码），不要写「它报错了」这种转述。转述会丢掉关键细节，过半年你自己都看不懂当时发生了什么。

**「教训」里要给一句能背下来的话。** 笔记是给未来的你查的，不是给现在炫耀的。

## 文件命名

全部小写，用连字符分隔，一个主题一个文件：

```text

├── _template.md            写新笔记时复制这个
```

## 还没写的

你手上已经有材料了：

**`compile-stages.md`** —— 你跑过 `gcc -E / -S / -c` 并把 `.i` `.s` `.o` 都看过了。把看到的东西记下来：

- 为什么 `.i` 文件有几百行？（`#include<stdio.h>` 被原样塞进来了）
- `.s` 里的汇编你认识几个？
- 四步各自做了什么？
