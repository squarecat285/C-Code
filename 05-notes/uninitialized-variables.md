# uninitialized-variables：没赋过值的局部变量，是别人留下的垃圾

- **日期**：2026-10-14
- **出处**：`01-textbook/sequence/change_maker.c`
- **关键词**：未初始化、局部变量、栈、未定义行为、32758

## 现象

输入不是数字时（`scanf` 失败了，什么都没读进去）：

```text
$ echo "abc" | ./change_maker
请输入应付金额 实付金额:应收: 1 元
实收: 32758 元      ← 见鬼了？
找零: 32757 元
50 元 * 655 张
```

问题出在这一行：

```c
int price, pay, change;    /* 只声明，没给初值 */
```

连跑三次，`32758` **每次都是同一个数**，看起来还挺"稳定"——但它依然是垃圾。

## 原因

C 语言**不会**自动把局部变量清零。

`int price;` 这种写法只做一件事：**在栈上要一块 4 字节的地**。至于这块地上原来有什么——那是上一个用这块内存的函数留下的残渣。你直接把它当成 `price` 来读了。

所以 `32758` 不是随机数，是**别人用剩下的数据**。

那为什么每次都一样？因为栈的布局和调用路径是固定的，同一段代码每次踩到同一块内存。**换编译器、开优化、加一个变量，它就会变。**

这种「结果看起来稳定，但其实没有保证」的行为，C 标准里叫 **未定义行为（Undefined Behavior, UB）**。UB 最恶心的不是它一定出错，而是**它有时对有时错，你还找不到规律**。

## 教训

声明的时候就给初值：

```c
int price = 0, pay = 0, change = 0;
```

这样即使 `scanf` 失败，也只会打印 0，不会打印内存垃圾。

**一句话记住它**：

> 声明变量时顺手给个 0。你没给，C 就不给——它会把你上次扔掉的数据还给你。
