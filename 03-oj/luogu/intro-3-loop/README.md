## 这一组要注意的

- **计数器用 `int`，累加器先用 `int` 想想能不能不碰小数。** P5719 就是个教训：答案要 `%.1f`，不代表中间结果必须用 `float`。
- **浮点的「有效位」和「小数位」是两件事。** `float` 只有 6~7 位有效数字，算出来的值差一丁点，`%.1f` 就会跨过 `.x5` 那条线，最后一位差 1。**看到要平均数先想 double。**
- **能边读边比，就别先存起来。** 找最小/最大、求和、计数，一个记忆变量加一趟循环就够，不需要数组。
- **`printf` 的格式串位置固定：** `%02d` 是「补零到 2 位」，`%2d` 是「补空格到 2 位」，`%d ` 会多打空格 —— 判题逐字节比，差一个空格就是 WA。
- **`while (a != 1)` 这类「条件终止」的循环，先想清楚初始值会不会已经满足条件。** P5720 的 `a = 1` 就是这种情况。
- **「把一个数的每一位拆出来」= `% 10` 取末位 + `/ 10` 去掉末位，套一个 `while (temp > 0)`。** P1980 是第一次用，以后判回文数、数位数、进制转换都是这一招。
- **要存下装不进 `int` / `long long` 的数，就一格一位地放数组里，个位放 `a[0]`。** 手工竖式怎么算，代码就怎么算；乘法和加法的收尾不一样（乘法进位可能好几位要用 `while`，加法最多 1 用 `if`）。
- **TLE 先看「你一共试了多少个候选」，而不是「你写得快不快」。** P1217 是最典型的例子：算法对、代码干净，照样 55 秒。降一个数量级的办法往往是**换个方向**——从「逐个检查是不是回文」改成「直接造回文」，候选从 5×10⁷ 掉到 1 万。
- **整数的小性质能砍掉一大半情况。** 偶数位回文一定能被 11 整除（`abba = 11 × (91a + 10b)`），所以 `b ≤ 10⁸` 时 2、4、6、8 位根本不用看。这类「同余/整除」的小结论，花五分钟推一下就顶一次优化。
