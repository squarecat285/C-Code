## 每道题的流程

1. **在 VS Code 里写**：在对应题组的文件夹下建文件，文件名先随便取也行，最后统一改
2. **本地跑一遍样例**：`Ctrl+Alt+N` 或 `F9` → `F5`，确认样例对得上
3. **交到洛谷**，拿到结果
4. **在文件末尾用 `//` 记下这题踩的错**，有几条写几条，不用讲究格式：

   ```c
   // === 过程记录 ===
   // 第一次 WA：printf("%.1f", rev / 10.0)，小数点插错位，小数位数也不够
   // 忘了把 float 乘 10 变成整数，n 一直是 0
   ```

5. **整理 + 上传**：末尾的「过程记录」挪进文件头的 `坑：` 字段；再补一段 `思路：`（怎么从题目想到这个算法的）；进度表补一行，然后提交推送

> 为什么错误先写在末尾？写代码的时候顺手在底下加一行最省事，不用往上翻。整理时再挪到头注释，顺便统一格式。

## 提交前自查

判题机不告诉你错在哪，所以交之前先自己过一遍：

- **输出格式**：有没有多余的提示语？行末有没有多 / 少空格？换行够不够？
- **边界值**：0、1、最大、最小、负数，都试了吗？
- **输入组数**：题目说的是读一组，还是「多组数据，读到 EOF」？
- **数组大小**：题目说 n ≤ 10⁵，就别开 100。
- **代码完整**：粘贴时**最后一行单独的那个 `}` 有没有一起选上**？交完看一眼「代码长度」和预览的最后一行，少一行就是少一个括号。

## 交完报错怎么看

- **Compile Error（CE）**：编译都没过，和算法无关。点开记录页的「**编译信息**」，那里有 gcc 的原始报错（中文的），照着它改。最常见的是括号没配对、少了分号。
- **Wrong Answer（WA）**：编译过了，答案不对。先自己拿边界数据跑一遍，再上手算一遍标准答案。
- **Runtime Error（RE）**：跑的时候崩了。除零、数组越界、递归太深，按这个顺序查。
