# 在线判题

按平台分子目录，目前是洛谷和 PTA。

## 洛谷

https://www.luogu.com.cn/

### 按题单分文件夹

一个洛谷题单一个文件夹，做完一组就换下一个，不要全堆在一层：

```
03-oj/luogu/
├── intro-1-sequence/         ← 【入门1】顺序结构
│   ├── README.md             ← 这一组的进度表
│   ├── P5705_digit_reversal.c
│   └── P1421_buy_supplies.c
└── intro-2-branch/           ← 【入门2】分支结构
    ├── README.md
    └── P5711_leap_year.c
```

### 命名约定

文件名用题目编号开头，后面跟一句简短的英文描述：

```
P5705_digit_reversal.c
P1008_three_division.c
```

### 每道题的文件头

字段顺序固定：文件名 → 来源 → 题目 → 日期 → **思路** → 要点 → 坑 → 建议（后三个按需）。

```
 * 题目：https://www.luogu.com.cn/problem/P1001
 * 日期：2026-11-02
 * 思路：1) 先把题目翻译成一句人话：……
 *       2) 由此推出要一个循环加一个记忆变量，而不是数组……
 *       3) 边界得单独想：n = 0 时循环一次都不进，结果是……
 * 坑：1) 第一次 WA，没考虑负数；
 *     2) 数组只开了 100，题目说 n ≤ 10^5，直接越界
```

**`思路` 记的不是代码在做什么，而是「怎么想出来的」**——题目里的哪句话，推出哪个中间结论，再落到哪段代码。隔一个月回来看，代码本身读得懂，值钱的是这条推理链；也正因为如此，`思路` 只写关键几步，不逐行翻译代码。

**记下「第一次为什么错」比记下「正确答案」有用得多。** 判题机不会放过任何一个边界情况，这正是它比课后题有价值的地方。

**不记「交没交、过没过」**——那是洛谷网站上的事，自己看提交记录就行，仓库里只留代码和踩过的坑。

### 错误先写在文件末尾

写代码的时候顺手在文件末尾用 `//` 记下踩的错，不用讲究格式；整理的时候再挪进头注释的 `坑：` 字段。详见 [`luogu/README.md`](luogu/README.md)。

### 刷题顺序

按题单顺序、不跳题。前 20 题会有点难受，之后就顺了。

## PTA

<https://pintia.cn/> → 题目集 → **团体程序设计天梯赛-练习集** → L1 基础级

目录：[`PTA/`](PTA/)，题目多但不分组，直接平铺在 `PTA/` 下：

```
03-oj/PTA/
├── README.md
├── L1-002_print_hourglass.c
└── L1-003_digit_count.c
```

命名同样用题目编号开头：`L1-002_print_hourglass.c`。头注释、`坑：` 字段、不记提交状态，规矩跟洛谷那边一样。
